# ClawBoard 制作思路

本文记录 ClawBoard 的**功能设计、使用指南与制作思路** —— 需求是怎么来的、为什么按这个顺序做、技术怎么选、中间卡在哪里、实测数字如何。想直接用的话，快速上手看 [README](../README.md) 与 [使用说明](./使用说明.md)。

## 一、项目概况

| 项目 | 内容 |
|---|---|
| 项目名称 | ClawBoard 悬浮剪切板 & 常用语面板 |
| 运行环境 | Windows 10 / 11 |
| 实现版本 | Python 版（完整功能）+ C 语言版（原生核心） |
| 第三方依赖 | **无**（仅用操作系统自带能力） |
| 代码规模 | Python 约 4200 行（含包拆分）/ C 约 2500 行 |
| 数据文件 | `ClawBoard数据.json`（UTF-8，可备份、两版互通） |

## 二、功能说明

ClawBoard 挂在屏幕一角，管两件事：**你复制过什么**、**你常要打什么**。

### 剪贴板历史
- 自动记录复制内容，重复复制只累计次数、不重复建条目
- 上限可配（默认 500 条），裁剪与清空**跳过收藏项**
- 悬停显示复制时间；右键查看详情（三个时间 + 来源 + 大小）

### 常用语
- 分组管理，可增删改、可命名
- **拆词**：一段文字按分隔符批量切成多条常用语（自动/换行/逗号/空格/分号/自定义六种）

### 高级搜索
- 语法：`app:` 来源、`time:` 时间、`type:` 类型、`size:` 大小、`is:` 状态、`-` 排除
- 多词 AND + 命中高亮；语法写错不崩，搜索框变红并提示原因

### 文本变换（27 项）
去格式、全角半角转换、大小写、驼峰/下划线、JSON 格式化、Base64、URL 编解码、MD5/SHA1/SHA256、提取 URL/数字、行排序去重、Markdown 转纯文本……

### 批量导出
TXT / CSV（带 BOM，Excel 打开不乱码）/ JSON / Markdown。

### 隐私保护
- 遵守 Windows 官方的「别记录我」剪贴板标记（密码管理器用它告诉监听者别记）
- 程序忽略名单（通配符）+ 窗口标题忽略名单（正则）
- 识别身份证 / 银行卡 / 手机号 / 邮箱 / Token / 密码串六类，默认打码显示
- 日志只写异常，**不写剪贴板内容**

### 交互
靠边自动隐藏、双击折叠贴右下角、窗口四边四角随意拉伸、界面等比缩放（50%~150%）、自定义背景色、亮/暗主题。

## 三、使用指南

### 启动
```bash
python ClawBoard.py          # 需 Python 3 + tkinter
```
或直接运行打包好的 `ClawBoard.exe`。C 版见 [`ClawBoardC/`](../ClawBoardC/)。

### 基本操作
| 操作 | 方式 |
|---|---|
| 唤出 / 隐藏面板 | `Ctrl+Shift+V`（被占用会自动降级为 `Alt+V`） |
| 粘贴某一条 | 单击条目（贴到上一个窗口） |
| 直接粘贴第 1~10 项 | `Ctrl+1..9` / `Ctrl+0` |
| 选中并移动 | `↑` `↓` 移动，`Enter` 粘贴 |
| 搜索 | 直接输入，或 `Ctrl+F` 聚焦 |
| 文本变换 | `Ctrl+T` |
| 批量导出 | `Ctrl+E` |
| 界面缩放 | `Ctrl+=` 放大 / `Ctrl+-` 缩小 |
| 删除选中 | `Delete` |
| 折叠成一条 | 双击标题栏 |
| 退出 | `Ctrl+Q`，或设置里「退出程序」 |

### 设置项说明
设置面板分两屏（见 [设置截图](https://pay-and-gain.github.io/ClawBoard/images/settings-general.png) / [进阶设置](https://pay-and-gain.github.io/ClawBoard/images/settings-advanced.png)）：

- **监听剪贴板**：总开关
- **单击后自动粘贴到上一窗口**：关掉就只复制、不自动粘贴
- **粘贴时去掉首尾空白**：从 PDF/网页复制的文本常带前导空格，默认去掉；只去首尾，**中间行缩进保留**
- **敏感内容打码显示 / 不入库**：六类敏感信息的两种处理方式
- **记录来源窗口标题**：默认关（隐私）；开了也会丢弃含"密码/银行卡/登录"的标题
- **靠边自动隐藏**：贴屏幕左/右/上边缘后自动收起
- **开机自启**：写当前用户注册表，不需要管理员权限；状态从注册表真实读取
- **界面缩放**：整体等比缩放（也可用 `Ctrl+=` / `Ctrl+-`）
- **全局唤起热键**：默认 `Ctrl+Shift+V`
- **忽略这些程序**：逗号分隔，支持 `*` `?` 通配（已预置 keepass 等密码管理器）

### 数据与安全
- 数据存在 `ClawBoard数据.json`，**纯文本、可备份、可迁移**
- 写文件采用「先写临时文件再原子替换」，不会写一半断电变成坏文件
- 版本升级前自动备份（保留最近 3 份）；读取时逐字段校验，坏字段回退默认值
- Python 版与 C 版**共用同一份数据文件**，可互换使用

## 四、制作思路

### 4.1 需求是怎么来的

这个工具是自己想用的，需求从"平时哪里不顺手"倒推出来，不是抄的功能清单：

- **剪贴板历史**：复制完就没了，想要能回看、能再粘贴
- **常用语**：有些话反复打（固定回复、地址），要有地方存、点一下就粘贴
- **形态像手机输入法的剪贴板**：挂屏幕右下角，不占地方，能拖能拉，不要一打开就铺满屏幕
- **功能只要这两个，不要更多**：明确"简洁版"——不要云同步、不要账号、不要花哨设置
- **常用语要能增删改**：添加、拆词、删除；每条能改内容和命名

后来追加的第二轮需求：隐藏时间戳、来源溯源、类型与大小徽章、高级搜索、文本变换、批量导出、粘贴为纯文本。

### 4.2 方法顺序：为什么按这个次序做

没有一上来就写全部功能，而是分了三批：

| 批次 | 内容 | 为什么放在这个位置 |
|---|---|---|
| 第一批（能跑起来） | 悬浮窗口 + 剪贴板监听 + 常用语分组 + 拆词 + 增删 | 先把"每天真的会用"的部分做出来，做完程序就能替我干活，后面每批都是在能用的基础上加 |
| 第二批（地基加固） | 系统托盘、全局热键、单实例互斥、虚拟滚动、崩溃日志、亮/暗主题 | 第一批只是"能跑"，常驻软件必须解决：怎么唤出来、怎么不重复启动、1 万条会不会卡、崩了数据会不会丢 |
| 第三批（数据增值） | 时间字段与迁移、来源溯源、类型徽章、高级搜索、文本变换、批量导出、纯文本粘贴 | 这些功能全部依赖第二批的字段与架构。比如"按来源搜索"必须先有来源字段，顺序反了就要返工 |

**一句话：先能跑 → 再跑得稳 → 最后才堆功能。**

### 4.3 技术选型：为什么是 Python，又为什么补一个 C 版

| | Python 版 | C 语言版 |
|---|---|---|
| 定位 | 主力版本，功能完整 | 原生核心，验证同一套设计能否脱离解释器 |
| 界面 | tkinter（Python 自带） | 纯 Win32 API + GDI 自绘 |
| 依赖 | 零第三方库 | 零第三方库，只链接系统 lib |
| 体积 | 打包后约 12 MB | 约 205 KB |
| 常驻内存 | 约 66–75 MB | 约 15 MB |
| 功能覆盖 | 全部（含高级搜索、27 项变换、导出） | 核心子集（监听/历史/常用语/拆词/托盘/热键等） |

选型的实际理由：
- **Python 版先做**：界面逻辑复杂（分组、虚拟列表、弹窗），写完能立刻改，迭代快。
- **C 版后做**：它验证的是另一件事 —— 同样功能去掉解释器能压到多小。205 KB / 15 MB 这个数字，用 Python 做不到。
- **两版共用同一份 UTF-8 JSON 数据文件**，可互相切换，历史不丢。

### 4.4 实现步骤（按实际做的顺序）

**第 1 步：把窗口做成"悬浮小面板"**
- 去掉系统边框（`overrideredirect` / `WS_POPUP`），自己画标题栏
- 置顶 + 半透明（约 97% 不透明度）
- 标题栏拖动、四边四角拉伸、双击折叠成一条
- 首次启动位置算在屏幕右下角，之后记住上次位置和大小

**第 2 步：让程序知道"我复制了什么"**
- Windows 剪贴板有两种做法：轮询读、或系统事件通知
- Python 版用剪贴板序号变化检测（`GetClipboardSequenceNumber`），序号变了才去读
- C 版用系统通知（`AddClipboardFormatListener`），有变化系统主动告诉程序
- **关键坑**：程序自己写回剪贴板（点击粘贴）时也会触发"剪贴板变了"，不处理的话粘贴一次就多一条重复记录。解决办法是写回后立刻同步序号，让监听器认出"这是我自己写的"

**第 3 步：常用语与拆词**
- 常用语按分组存，每组是若干条「名称 + 内容」
- 拆词支持六种分隔方式；每条能改内容、改名字、删除

**第 4 步：让它能常驻**
- 托盘图标：点 ✕ 是隐藏不是退出，托盘右键菜单才是真退出
- 全局热键；单实例互斥（双击第二次不会开两个，而是把已开着的叫到前台）
- **虚拟列表**：1 万条历史时只创建屏幕上看得见的 9 个控件，滚动时复用 —— 这是"1 万条不卡"的关键

**第 5 步：给每条记录补上元数据**
- 三个时间分开存：首次复制 / 再次复制 / 最近粘贴。重复复制只加计数，不改首次时间
- 来源进程、类型与大小（入库时判定一次并缓存）
- 老数据没有这些字段 → 写版本化迁移：升级前自动备份，老记录按序号推算时间并标记"估算"，界面显示"约"字，不假装精确

**第 6 步：让元数据能查（高级搜索）**
- 解析器写成独立模块，不依赖界面，可单独测试
- 语法写错不崩，搜索框变红提示

**第 7 步：文本变换与导出**
- 27 个变换函数，每个都是独立纯函数
- 导出 CSV 特意带 BOM，用 Excel 打开中文不乱码

**第 8 步：C 语言重写核心**
- 纯 C + Win32 API，界面全部 GDI 自绘（自己画卡片、滚动条、按钮），托盘图标运行时 GDI 生成，不需要任何图片资源
- 自己写迷你 JSON 解析器，让 C 版能直接读 Python 版写的文件

### 4.5 做的时候真正卡住我的几个点

| 问题 | 现象 | 怎么解决的 |
|---|---|---|
| 弹窗掐断监听 | 打开输入框时主循环被阻塞，期间复制的一条都记不下来 | 弹窗改成非阻塞，用"确定后回调"代替"等它返回" |
| 全局热键注册失败 | 一直返回错误码 1408 | 窗口在子线程创建、注册却在主线程调。改成在消息线程里注册且不绑定窗口（用空句柄），热键消息直接进该线程循环 |
| 粘贴时焦点抢不回来 | 内容进了剪贴板但没粘到目标窗口 | 先隐藏自己 → 把焦点还给上一个前台窗口 → 模拟 Ctrl+V；目标窗口是管理员权限（会被系统拦）时检测失败并提示"已复制，请手动粘贴" |
| 列表一多就卡 | 几千条时滚动明显掉帧 | 固定行高 + 只渲染看得见的几行；滚动时缓存宽度避免重复调用界面接口 |
| 老数据升级 | 新版加了字段，老文件直接读会出错甚至丢数据 | 版本化迁移：升级前备份 `.bak`，失败自动还原；无时间戳的老记录标"估算" |
| 压测数据写脏用户文件 | 跑性能测试退出时，1 万条测试数据被存进真实数据文件 | 压测模式改成退出时不保存 |
| 函数挂错系统库 | `CreateMutexW`、`Shell_NotifyIconW` 报"找不到函数" | 它们分别在 kernel32 和 shell32，不在 user32 |

### 4.6 实测数字

**Python 版**（1 万条历史，压测模式）：

| 指标 | 实测值 | 目标 |
|---|---|---|
| 启动到能用 | 350 ms | < 800 ms |
| 常驻内存 | 66.6 MB（1 万条时 74.4 MB） | < 80 MB |
| 搜索一次 | 9.2 ms | < 50 ms |
| 高级语法搜索一次 | 5.0 ms | < 50 ms |
| 空闲时 CPU | 0.00 % | ≈ 0 % |
| 1 万条实际创建的控件数 | 9 个 | 虚拟化生效 |

**C 版**：可执行文件 205 KB，运行内存约 15 MB，MSVC 编译零警告。

**回归测试**：监听入库、保存后重开数据一致、搜索、热键、托盘、设置开关、单实例、敏感识别、常用语增删、键盘操作、主题切换、老库 300 条升级一条不少 —— 全部通过。

### 4.7 常见问题

**Q：为什么不用现成的剪切板软件？**
A：现成的要么功能太多（云同步、账号、收费），要么不能自定义常用语分组。我要的只是"复制历史 + 常用语"，而且要挂在右下角不挡视线。自己做可以精确到每个细节。

**Q：零第三方依赖是真的吗？**
A：是真的。界面用 Python 自带的 tkinter，系统能力（剪贴板、托盘、热键、进程查询）全部用 ctypes 直接调 Windows API。好处是：不用联网、不会被库版本坑、换台电脑复制过去就能跑。

**Q：为什么同一个东西做两遍（Python 和 C）？**
A：不是为了凑数。Python 版"先把复杂逻辑跑通"，C 版"验证这套设计脱离解释器能有多小"。结果是 12 MB / 66 MB 对 205 KB / 15 MB，差了几十倍 —— 这个对比本身就是我想搞清楚的问题。

**Q：数据会不会丢？**
A：三道保险。① 写文件先写临时文件再替换，不会写一半变成坏文件；② 版本升级前自动备份；③ 读取时逐字段校验，缺字段补默认值、坏字段回退，不会因一条脏数据整个程序打不开。

**Q：隐私怎么处理？**
A：识别身份证/银行卡/手机号/邮箱/Token/密码串六类，列表里默认打码，可一键看原文，也可设成"检测到就不入库"。来源窗口标题默认不记录。日志只写异常，不写剪贴板内容。

### 4.8 还能继续做的方向

- 图片剪贴板：目前两个版本都只处理文本
- C 版的靠边隐藏与开机自启（目前只在 Python 版里有）
- 多显示器不同缩放比下的细节打磨
