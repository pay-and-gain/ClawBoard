# ClawBoard 大版本升级提案 R1

日期：2026-10-25。状态：**A+C已确认，M1已实施；本提案保留候选对照，不是全部已发布功能清单**。

后续进展：用户已确认A主视觉＋C按需工作台。M1首批正式Tk界面已实施并在本机升级；以下保留原提案和候选对照，当前实施状态以PROGRESS.md为准。

建议定位：**把零散信息安全收拢成随手可用的材料，帮助个人更快回到正在做的事。**

“3.0”暂作下一大版本的规划名，当前产品 `APP_VER=2.7.0` 不变。产品研究、独立脑暴和评分原稿另存本机私有研究目录；本文件只记录筛选后的本产品方案。

## 1. 两个要求合并，而不是二选一

1. 正规产品调研、当前能力核实、功能差距、UI/图标重设计。
2. 空白上下文跨领域脑暴15个方向，再按价值、可行性和数据控制筛选；允许新的工作流超出剪贴板。
3. 研究与决策存盘、每阶段有独立版本、关闭聊天/程序后能从记录恢复工作。

第一阶段制作三套合成数据交互草案、四个原创矢量图标文件，并保留旧版回退点；随后已按A+C实施M1首批并更新本机。当前状态见PROGRESS.md。

## 2. 推荐的产品形态

**一个轻量入口，两个使用深度。**

- **快速面板**：仍然用于热键唤起、搜索、单击粘贴，保留小窗口。来源/大小默认隐藏，底部搜索保持短，删除与拆词相邻，单次短反馈。
- **按需工作台**：用户主动展开后管理项目口袋、长期素材、可复用处理配方与拼装大纲。关闭工作台不影响后台采集；功能默认不挤占快速面板。
- **内置可选模块**：模块是同一程序中按需显示的功能，不是任意第三方插件执行环境，不引入新的 pip 运行依赖。

本轮最推荐验证的两种跨领域工作流：

1. **项目口袋 / 续上昨天**：把主动选中的片段、链接、文件引用、备注和“下次先做什么”收成一个可重启恢复的小项目。可导出离线材料包；不能只依赖会被历史容量淘汰的条目ID。
2. **受控处理配方 / 小工序作坊**：将最多三步已有文本变换保存为配方，重复使用时先看完整结果，再复制或导出；原文不变。素材大纲/证据视图保留到二期，避免首批同时做完整编辑器。

初期手动组织即可，不依赖AI生成、自动读取窗口或自动收集全盘文件。

## 3. 三套视觉方案

交互草案入口：本目录 `index.html`，全部资源本地可用；`prototype.css` / `prototype.js` 是浏览器演示，不是产品技术栈迁移。

| 方案 | 外观与图标 | 主要优势 | 真实取舍 |
|---|---|---|---|
| **A 纸感·爪印（推荐）** | 纸张白、墨绿、轻分隔；纸张＋爪印原创标志 | 安静、耐看，有一点可爱；最容易保持小窗口效率 | 不能靠留白牺牲列表密度，需保留紧凑档 |
| B 软糖·小猫夹 | 奶白、浅紫、柔和圆角；猫脸＋夹子 | 亲和力和识别度强 | 小尺寸图标要另画；装饰需克制，避免幼稚和低对比 |
| C 专注·工作台 | 清晰蓝灰、分栏分类与完整预览；叠页图标 | 适合长文、代码、项目材料整理 | 不适合默认替换所有小面板；窄窗必须自动收起分栏 |

**建议采用 A 的主视觉，C 的布局只作为按需工作台；维护同一套控件与主题，不维护三套产品。** B可作为后续外观主题，但不承诺首批同时完成三种主题。

共同设计规格：

- 4/8像素逻辑间距体系；正文、辅助信息、动作三个清楚层级；不用多个强调色竞争。
- 统一原创线性图标；不把Emoji字体当作图标系统；图标操作提供文字提示、键盘入口和可见焦点。
- 控件以可聚焦Tk按钮/标准输入为基础；避免为了圆角把所有东西改为无语义Canvas。
- 浅/深主题、减少动画、高对比场景一起设计；普通小字对比目标≥4.5:1，选中/错误/暂停不只靠颜色。
- 应用ICO拟包含16/20/24/32/40/48/64/128/256像素；托盘另做简化轮廓和暂停状态，不能仅缩小复杂头像。
- Windows窗口按钮/焦点习惯保留；借鉴简洁层次，不复制Apple专有图形或承诺等价玻璃效果。

## 6. 三个可验收里程碑

### M1：看起来统一，用起来稳定

范围：选定主视觉、图标、统一控件、分组设置、可视筛选、按需预览、键盘焦点。

门槛：最小280逻辑像素主窗核心动作全部可达；双屏125%/150%和五档用户缩放、长中文/空结果/大字体通过；单击粘贴/热键/托盘/输入法和权限降级无回退。不得用浏览器原型代替真实Tk验收。

### M2：保存、整理、撤销、恢复形成闭环

范围：完整备份恢复/导入、保存状态、跨重启回收站、备注/集合/保存搜索、多项合并。

门槛：合成库新进程重载一致；图片与引用计数一致；损坏包、超限包、路径穿越、磁盘写失败、恢复中断均保留原库；导入先备份和预览；图片回收不破坏回收站/项目素材。不存在“只在进程内有效”却宣传为已持久化的功能。

### M3：最多两条跨场景工作流先证明收益

范围：先评估项目口袋和受控处理配方，模板/配方/队列按各自验收逐步接入，不把28项一次塞进首发。

门槛：给定10条合成材料，用户能创建项目、留下下一步、关闭程序后恢复；材料不会因普通历史淘汰而失效。最多三步受控配方能逐步预览，失败或取消不改原文，配方保存后新进程仍可重用。大纲/证据视图和有来源回链的组合导出放到二期验收。若接入连续粘贴，必须能取消，焦点/权限变化立即停。新功能需比手动流程省步骤，且日常小面板无需学习全部模块。

各阶段均运行现有回归、新增功能专项脚本及独立Windows真实交互验收。性能用同设备/同合成库比较：先记录基线，默认未展开功能不得造成明显持续CPU或内存增长；主线程交互p95超过基线10%或稳定内存增加超过15%时需解释和优化，不把一次跑分当长期稳定证明。

## 7. 数据、兼容与技术边界

- 运行时继续标准库、tkinter、ctypes。原型网页仅为设计交付。
- 共享JSON已有字段语义不变。备注、集合、保存查询使用可选字段并做Python/C往返测试。
- 项目可以保存明确标记的外部文件引用，但必须说明“未复制文件正文、未备份”，路径失效时可见。**承诺在包内长期保存的材料必须拥有完整副本/图片资产，不能只依赖会过期的历史ID或截断预览。**
- 较大的工作空间可评估单独版本化旁文件与独立素材目录；实现前先确定跨文件备份一致性、图片GC、限额和旧版忽略契约，不在方案阶段悄悄迁移数据库。
- 本地OCR当前微软文档有桌面包身份限制；便携模式、语言包与零pip路线必须先实证，不直接承诺“已能免费离线识字”。
- DPAPI依赖用户/机器身份的默认行为，不能直接等同跨机便携密码库。现有共享JSON不得原地换成密文；加密独立方案先设计恢复路径。
- 来源链接/外部文件由用户显式打开，限制协议；剪贴板内容不能变成自动执行命令。
- AI/同步/网页缩略图请求均不隐式开启。先说明具体内容、去向与控制方式，保留纯本地完整工作流。
- 测试永远使用临时路径＋构造App前NO_SAVE，核对真实库。恢复/保存专项只在独立合成库允许实际写入。
