悬浮剪贴板 & 常用语面板

Floating clipboard & phrases panel

Windows · 零第三方依赖 · Python 与纯 C 双版本

Windows · Zero third-party dependencies · Python and pure C builds

贴在屏幕一角的轻量面板，管两件事：你复制过什么、你常要打什么。支持搜索、文本变换、批量导出、快速粘贴，以及一整套面向隐私的剪贴板处理机制。

A lightweight panel docked in a corner of your screen that handles two things: what you copied and what you type often. With search, text transforms, batch export, quick paste, and a full set of privacy-oriented clipboard handling.

数据与安全

Data & safety

  • 数据存 ClawBoard数据.json，纯文本、可备份、可迁移
  • 写文件采用「先写临时文件再原子替换」，不会写一半变成坏文件
  • 版本升级前自动备份（保留最近 3 份）；读取时逐字段校验
  • Python 版与 C 版共用同一份数据文件，可互换使用
  • Data lives in ClawBoard数据.json — plain text, easy to back up and migrate
  • Writes go to a temp file and are atomically swapped in — no half-written file
  • Automatic backup before schema upgrades (keeps the last 3); per-field validation on read
  • The Python and C builds share the same data file and can be swapped freely

设计思路要点

Design highlights

  • 先能跑 → 再跑得稳 → 最后才堆功能：分三批做，第一批就能日常使用，后面每批都在可用的基础上加
  • 为什么不用现成软件：现成的要么功能太多（云同步/账号/收费），要么不能自定义常用语分组
  • 为什么做两个版本：Python 版验证复杂逻辑，C 版验证脱离解释器能压到多小 —— 12 MB/66 MB 对 205 KB/15 MB
  • 1 万条不卡的关键：虚拟列表，屏幕上只创建看得见的 9 个控件
  • 三道数据保险：原子写 + 升级前备份 + 逐字段校验
  • Make it run → make it stable → then pile on features: three batches; the first is already usable daily
  • Why not an existing tool: they're either overloaded (cloud sync / accounts / paywalls) or can't do custom phrase groups
  • Why two builds: Python gets the complex logic working, C proves how small the same design gets — 12 MB/66 MB vs 205 KB/15 MB
  • Why 10k items don't lag: a virtual list keeps only the ~9 visible widgets alive
  • Three data safeguards: atomic writes + pre-upgrade backup + per-field validation
